# PostgreSQL source schema

`schema.sql` khởi tạo **28 bảng nguồn trên PostgreSQL 16**, không chứa dữ liệu. Khi chạy `make up`, `platform-admin-init` áp dụng schema nguồn trống và chỉ tạo admin bootstrap; seed catalog chạy thủ công. Quyền MinIO/Polaris và credential workload được quản trị trên Streamlit. Xem [phạm vi API nguồn](../docs/ARCHITECTURE.md#1-phạm-vi-và-hiện-trạng).

## Định nghĩa và tái lập

- [ORM](../services/platform-app/src/platform_app/api/models/) định nghĩa cột, default, CHECK, FK và index.
- [schema.sql](schema.sql) là bản SQL bootstrap được render từ ORM, bổ sung trigger `updated_at`. `Base.metadata.create_all()` riêng lẻ không cài các trigger này.
- [OLTP_SCHEMA](../docs/DATA.md#2-schema-oltp) mô tả hợp đồng dữ liệu, cursor và giới hạn chuyển đổi.
- [seeds/](seeds/) chạy thủ công, bổ sung từng bản ghi tham chiếu còn thiếu và giữ dữ liệu đã có; không tự chạy khi API khởi động.

Render hoặc kiểm tra file SQL từ thư mục gốc:

```bash
uv run --locked --package platform-app -- \
  python -m platform_app.api.db.schema --output database/schema.sql
uv run --locked --package platform-app -- \
  python -m platform_app.api.db.schema --output database/schema.sql --check
```

Hai lệnh này chỉ đọc ORM và ghi/so sánh file, không kết nối database. Sau khi đổi ORM phải render lại và review diff. Cột/constraint/index được sắp xếp ổn định để kết quả tái lập qua process.

## Bootstrap database trống

PostgreSQL init tạo database/user `ecommerce`, `airflow`, `polaris`. Khi chạy `make up`, `platform-admin-init` tiếp tục tạo bảng nghiệp vụ trên schema trống và admin cấu hình qua `API_BOOTSTRAP_ADMIN_*`; giữ dữ liệu/password nếu schema đã đủ, từ chối schema dở dang. Không chạy lại DDL bên dưới sau bước này.

Nếu chỉ chạy PostgreSQL, có thể nạp schema thủ công vào database nguồn trống:

```bash
docker compose exec -T postgres sh -c \
  'PGPASSWORD="$POSTGRES_ECOMMERCE_PASSWORD" exec psql -X -v ON_ERROR_STOP=1 --host=127.0.0.1 --username="$POSTGRES_ECOMMERCE_USER" --dbname="$POSTGRES_ECOMMERCE_DB"' \
  < database/schema.sql
```

DDL chạy trong một transaction: tạo đủ bảng trước, thêm FK sau để xử lý quan hệ vòng, rồi tạo index/function/trigger. Không tắt FK, không DROP bảng, không seed hoặc chạy pipeline. File không phải migration và không dùng để nâng cấp database đã có dữ liệu. Với database khác, dùng psql chọn đúng database/user tương ứng.

`API_DATABASE_URL` là cấu hình bắt buộc, dùng `postgresql+psycopg2`. `.env.example` có URL cho host; Compose inject URL riêng dùng hostname `postgres`. Session API đặt UTC và search_path public.

## Seed và dữ liệu lịch sử

Từ root repo, cấu hình `.env` cho `API_DATABASE_URL` host và `API_SECRET_KEY` như `.env.example`. Sau bootstrap schema:

```bash
# Seed catalog/admin trong một transaction
make seed
```

Trong container đã build mới, có thể dùng `docker compose exec -T platform-app python -m database.seeds.seed_catalog`.

**Dữ liệu lịch sử** do lệnh `datagen` nạp sau khi seed: `make generate PRESET=1m` đọc preset `generator/oltp/configs/*.yml` và ghi 12 tháng khách, đơn, giao vận, trả hàng và sổ kho; lineage `data_origin='synthetic'`/`generation_run_id` nằm trên customers/orders; xem [generator](../generator/README.md). Seed **không tạo `cities`/`stores`**; hai bảng này do generator tạo, nên database chỉ có seed thì các luồng cần cửa hàng phải tự chuẩn bị địa điểm.

Schema hiện bỏ hai CHECK tồn hiện tại không vượt tồn đầu: `opening_on_hand` là mốc cố định, nhập/nhận/trả hàng đi qua ledger. Database đã có schema cũ cần được cập nhật và đối soát riêng; bootstrap không tự nâng cấp hay sửa dữ liệu.

## Hợp đồng dữ liệu

- UUID native, nhận `uuid.UUID` hoặc chuỗi UUID qua ORM; không lưu binary 16 byte.
- Thời gian là `TIMESTAMPTZ`; API ghi datetime UTC có tzinfo. Default/trigger dùng `statement_timestamp()`, không phụ thuộc timezone session.
- Identity dùng `GENERATED BY DEFAULT`: nhận ID tường minh khi nạp lịch sử. Công cụ nạp ID tường minh phải tự đồng bộ identity sau khi nạp (ví dụ `ALTER SEQUENCE … RESTART`, không giảm sequence).
- ID và tiền dùng BIGINT; bộ đếm nhỏ (số lượng, lượt thử, rating, `boom_count`…) dùng INTEGER. CHECK không âm chỉ đặt trên tiền, bộ đếm và version, không đặt trên ID/FK. VND là số nguyên, không có cột `currency_code`.
- Giữ computed column và unique guard cho mỗi khách chỉ một giỏ active. Mã do người nhập (danh mục, slug, SKU, size/màu, thành phố, cửa hàng) unique theo `lower()`; khóa API đã chuẩn hóa (email, mã đơn/coupon/trả hàng, idempotency key…) dùng unique thường. Không phân biệt dấu (accent-insensitive) chưa được hỗ trợ. Hành vi tra cứu/tìm kiếm thuộc phần nghiệm thu API sau.
- `updated_at` tự tăng khi dữ liệu đổi mà timestamp không được đổi tường minh; timestamp lịch sử khác giá trị cũ được giữ. No-op không tăng, kể cả bảng có cột generated. Trigger timestamp không tự tạo ledger/history nghiệp vụ.
- Mỗi yêu cầu trả hàng có tối đa một refund (`refunds.return_id`); refund hủy đơn không có `return_id` và unique theo payment.
- Dòng `inventory_transactions` trỏ tới tối đa một chứng từ (`order_id`, `receipt_id` hoặc `return_id`); CHECK bắt buộc chứng từ đúng loại theo `movement_type`. Chuyển kho và điều chỉnh không cần chứng từ.
- `orders.shipping_city_id` (tùy chọn) lấy từ `shipping_city_code` khi checkout.
- Có 318 cột và 56 FK, khớp với ORM. Reader batch được SELECT 27 bảng (trừ `customer_credentials`); batch nạp 19 bảng và chỉ đọc `inventory`/`store_inventory` để đối soát sổ kho.

## Kiểm tra

```bash
# Đối chiếu DDL với ORM, không kết nối PostgreSQL:
uv run --locked --package platform-app -- \
  python -m platform_app.api.db.schema --output database/schema.sql --check
# Khi có sẵn thư mục tests local:
uv run --locked --package platform-app -- \
  python -m unittest discover -s services/platform-app/tests -v
```

ORM hiện có **28 bảng, 318 cột và 56 FK**. Lệnh `--check` xác minh bản DDL được render khớp code; nó không chứng minh database đang chạy đã được migrate.

Các kiểm tra nền tảng/DDL và test quản trị không thay thế nghiệm thu toàn bộ giao dịch, pipeline và tập dữ liệu lớn. Chi tiết phạm vi kiểm chứng ở [operations](../docs/OPERATIONS.md#7-kiểm-tra-chất-lượng-và-ci).

## Tài khoản đọc cho batch PostgreSQL

Sau bootstrap đủ bảng, đặt `POSTGRES_ECOMMERCE_READER_USER=ecommerce_reader` và password riêng trong `.env`; Compose truyền chúng vào PostgreSQL/Airflow/batch client. Cập nhật container PostgreSQL để nhận biến/mount mới rồi chạy `make source-reader`. Lệnh gọi `infrastructure/postgres/configure-source-reader.sh` bằng tài khoản quản trị PostgreSQL trong container, tạo/cấu hình role chuyên dụng trong một transaction; không tự chạy khi startup và không thay schema hay dữ liệu nghiệp vụ.

Role chỉ SELECT 27 bảng nguồn phân tích (batch nạp 19 bảng, hai bảng tồn kho dùng để đối soát), không có quyền đọc `customer_credentials` hoặc quyền ghi bảng/sequence. Không dùng role ứng dụng/admin; script từ chối role có đặc quyền, membership hoặc sở hữu database/schema/relation. Mặc định phiên là UTC/read-only. Không grant mặc định cho bảng mới; khi whitelist thay đổi phải review và chạy lại. Script có thể áp lại password cấu hình khi chạy lại; đây không phải công cụ migrate database cũ. Cách batch dùng role này xem [pipeline OLTP](../airflow/README.md#connections-and-credentials).

## Metadata Superset tùy chọn

`make superset-db` chạy script PostgreSQL riêng sau khi áp dụng env/mount mới, tạo database/user `superset` với password được cấu hình. Script hỗ trợ volume đang có, không sửa schema/dữ liệu nguồn và giữ password của role đã tồn tại. `make superset-init` mới thực hiện migration metadata Superset và tạo admin ban đầu. Xem [hướng dẫn BI](../docs/SETUP.md#6-superset-tùy-chọn); không dùng account OLTP/Polaris/Airflow làm owner metadata này.
